# edge-fleet-operator-demo

A small, fully runnable demonstration of cloud–edge fleet management in Go:
a Kubernetes **Operator** (kubebuilder v4 / controller-runtime) drives desired
state, and a **stdlib-only edge agent** (one static binary, zero dependencies)
executes A/B firmware updates on simulated devices — with batched rollouts,
a circuit breaker, heartbeat health, and optimistic-concurrency handling shown
end to end on a local `kind` cluster.

This is a portfolio project: deliberately small (~1,400 lines of hand-written
code, every line explainable), with "why" comments at each design decision
instead of feature completeness.

```
[kubectl apply FleetRollout] ─────► FleetRollout controller
                                        │  writes device Spec, batch by batch
                                        │  (maxUnavailable, circuit breaker)
                                        ▼
[kubectl apply EdgeDevice CR] ────► EdgeDevice CR (Spec = intent, Status = fact)
                                        ▲│
                        status updates  ││  watch / reconcile
                  (optimistic 409 dance)││
                                        │▼
                                EdgeDevice operator
                                        │  phase projection, heartbeat timeout,
                                        │  credential Secret, finalizer cleanup
                                        │
        ┌───────────────────────────────┴──── (device side: poll w/ jitter) ──┐
        ▼                          ▼                              ▼
  agent (dev-0)              agent (dev-1)   ×N            agent (dev-N)
  Idle→Downloading→Verifying→Flashing→Confirming→Idle
        │ Range-resume download        │ SHA256 at every boundary
        ▼                              ▼
  firmware-server (HTTP)         slotA/ slotB/ + `current` symlink
                                 (.pending = bootcount, .confirmed = sealed)
```

## Quick start

Requires Linux or WSL2 with Docker, Go 1.22+, kind, kubectl, kubebuilder.

```sh
make kind-up             # create/repair kind cluster + install CRDs
make ci                  # go vet + unit tests + envtest controller tests

make demo-rollout        # 5 devices, batched upgrade, device death, breaker
make demo-conflict       # stale write → 409 → re-read → latest wins
make demo-brick-safety   # bad checksum: firmware never flashed
make clean               # tear everything down
```

For hands-on poking: `make run-agents N=5` plus `make run-operator` in a
second terminal, then edit device Specs with kubectl. Operator metrics
(controller-runtime defaults: reconcile totals, errors, durations, queue
depths) are at `http://localhost:8080/metrics` while `run-operator` is up.
Agents log every state transition via `log/slog`.

## What is hand-written vs generated

Generated by kubebuilder and controller-gen: `config/`, `cmd/main.go` (minus
the `--heartbeat-timeout` flag), `zz_generated.deepcopy.go`, the Makefile
skeleton, test suite scaffolding. Hand-written (~1,400 lines of code, ~900
lines of tests):

| Area | Files |
|---|---|
| CRDs | `api/v1alpha1/edgedevice_types.go`, `fleetrollout_types.go` |
| Operator | `internal/controller/edgedevice_controller.go`, `fleetrollout_controller.go` |
| Agent (stdlib only) | `internal/agent/{agent,fsm,download,slot,kube}.go` |
| Binaries | `cmd/agent/main.go`, `cmd/firmware-server/main.go` |
| Demos | `hack/*.sh` |

Verify the agent's zero-dependency claim:

```sh
go list -deps ./cmd/agent | grep -c k8s.io    # → 0
```

## Design decisions

**Spec/Status separation.** Spec is intent, Status is observed fact, and
reconcile is the engine that drives fact toward intent. They are separate
subresources with disjoint writers: users/rollout write Spec; the agent writes
firmware facts; the operator writes health facts. No two writers share a
field, so field-level fights are impossible by construction
(`api/v1alpha1/edgedevice_types.go`).

**Two idempotency gates.** Reconcile is level-triggered — it learns *that*
something changed, never *what* — so every pass must be repeat-safe. Gate 1:
project the status we would write and skip the write when it matches (no
redundant PUTs, which would trigger yet more events). Gate 2: before any side
effect, check existence + a UID fingerprint — the credential Secret is created
exactly once, and a device recreated under the same name gets its credential
rotated, not reused (`internal/controller/edgedevice_controller.go`).

**`return err` vs `RequeueAfter`.** `return err` means "something broke,
retry with exponential backoff" and counts against error metrics.
`Result{RequeueAfter}` means "all is well, wake me at T" — planned, precise,
not an error. Heartbeat expiry is a planned future event, so it uses
RequeueAfter aimed at the exact deadline; conflating the two gives you noisy
error rates and random detection latency.

**409 handling: conflict is not an error — it is the signal that the latest
state wins.** Every agent status write carries the resourceVersion it read
(`PutStatus`); when the object moved on, the API server answers 409, and
`UpdateStatus` reacts the only correct way: throw away the stale local view,
GET the fresh object, re-apply the mutation, write again
(`internal/agent/kube.go`). Retrying the old payload would silently overwrite
someone else's write. `make demo-conflict` replays this with kubectl, and the
device that was offline through two spec changes converges directly to the
*latest* target, skipping the intermediate one.

**A/B confirm-or-rollback.** Firmware lands only in the inactive slot; the
running slot is never touched. Promotion writes a `.pending` marker (its
content is a boot-attempt counter — bootcount semantics) *before* the atomic
symlink flip; a trial boot must self-check and `.confirm`, and a crash before
confirmation means the next boot rolls back to yesterday's slot
(`internal/agent/slot.go`). SHA256 is verified at every boundary where bits
moved: after download, after staging, at self-check.

**Single-flight guard.** One upgrade transaction at a time, enforced with a
mutex + flag rather than a queue: intermediate targets are worthless (if the
spec moved v1→v2→v3 mid-flash, flashing v2 next is wasted), and the CR is
already a mailbox that holds only the latest intent. After a transaction
finishes, the next poll reads whatever is newest — latest-wins for free
(`internal/agent/agent.go`).

**Rollout batches are emergent, not stored.** The FleetRollout controller
keeps no cursor; every reconcile lists the fleet, counts
selected/targeted/succeeded/failed, and tops up in-flight devices to
`maxUnavailable`. A controller restart costs nothing. When
`failed/targeted` crosses the threshold the breaker trips: the rollout pauses
itself and stamps `rolloutPaused=true` on every selected device — and never
un-trips itself (`internal/controller/fleetrollout_controller.go`).

## Differences from production

Honest list of what this demo simplifies:

- **Transport**: agents poll the API server directly with jitter. Production
  edge (KubeEdge) is push over MQTT/WebSocket with an offline queue replaying
  missed updates on reconnect. The semantics that matter survive the
  simplification: sync is level-based — a reconnecting device reads the
  *latest* desired state, not a backlog of intermediates.
- **A/B switch**: two directories + a symlink stand in for partitions, and
  `.pending`/`.confirmed` markers stand in for the bootloader's bootcount
  (U-Boot / Android boot_control). The software contract is the real one:
  flash inactive, mark try-once, confirm after self-check, or get rolled back.
- **Security**: agents use the kind admin kubeconfig and the provisioned
  credential Secret is a stub. Production needs per-device identities
  (mTLS/tokens via an enrollment flow), least-privilege RBAC per device, and
  signed firmware, not just hashed.
- **Rollout strategy**: one batch knob + a global failure-rate breaker.
  Production adds canary steps, region/zone ordering, and per-batch windows.
- **Kubeconfig parsing**: the agent extracts exactly four fields from the
  flat kind-style file instead of shipping a YAML parser; real agents don't
  use kubeconfigs at all.

fleet:

    batch 1 (dev-0, dev-1) upgraded to 2.0.0

    circuit breaker tripped (rollout Paused)

NAME           PHASE    TARGET   SELECTED   TARGETED   SUCCEEDED   FAILED

dev-0   Ready      2.0.0     2.0.0     A      true     2s
dev-1   Ready      2.0.0     2.0.0     A      true     2s
dev-2   Ready      2.0.0     2.0.0     A      true     2s

`make demo-conflict` — the optimistic-concurrency dance:

```
>>> 2. Device 'goes offline' holding a snapshot of the object
    snapshot resourceVersion = 1872
>>> 3. While it is away, the spec changes TWICE (rv moves on without it)
    latest resourceVersion   = 1875 (device still holds 1872)
>>> 4. Device comes back and writes status FROM ITS STALE SNAPSHOT
    Error from server (Conflict): ... the object has been modified;
    please apply your changes to the latest version and try again
>>> 5. Conflict is not an error — it is the signal that the latest state wins.
    status written against fresh resourceVersion — accepted
NAME                DESIRED   CURRENT
conflict-demo-dev   3.0.0     1.0.0      ← device now chases 3.0.0 directly
```

`make demo-brick-safety` — corrupted image is refused before the switch:

## Testing

```sh
make ci    # go vet + everything below
```

- **Operator (envtest, real API server)**: idempotency proven by
  resourceVersion stability across repeated reconciles; credential rotation on
  fingerprint mismatch; finalizer revokes the credential before releasing
  deletion; all phase transitions including Degraded → recovery (with an
  injected clock — no sleeps); rollout batch sizing/advancement/completion,
  breaker trip + freeze + no-self-reset, Degraded-counts-as-failed.
- **Agent (pure stdlib unit tests)**: table-driven FSM transition matrix;
  download retry on 500s, mid-stream disconnect → Range resume (asserted on
  the server side), give-up after max attempts; A/B happy path,
  crash-before-confirm rollback (a fresh SlotManager simulates the reboot),
  checksum-mismatch never switches, self-check failure rolls back; 409 →
  re-read → re-apply semantics against a fake API server that enforces real
  resourceVersion checks.
